# رِواق المتون | Riwayq Al-Mutun

منصة عربية مجانية ومفتوحة المصدر تساعد طالب العلم على تنظيم حفظ المتون ومراجعتها، مع دعم العمل دون اتصال بالإنترنت (PWA).

## بنية التطبيق الحالية
- `index.html`: بوابة الأقسام الرئيسية الأربعة.
- `hifd.html`, `study.html`, `istidhar.html`, `review.html`, `progress.html`: وظائف الحفظ والدراسة والاستظهار والمراجعة والتقدم.
- `reading.html`: مكتبة ملفات PDF.
- `audio.html`: مكتبة MP3.
- `video.html`: مكتبة شروح MP4، وتُدار قائمتها من `videos.json`.
- `app.js`: منطق الحفظ والمراجعة والتقدم، مع الحفاظ على مفاتيح التخزين المحلية الحالية.
- `menu.js` و`theme.js`: التنقل والمظهر المشتركان.
- `sw.js`: التخزين المؤقت وتشغيل التطبيق بعد التحميل الأول.
- `mutun.json`: بيانات المتون ومقاطعها.
- `pdfs/`, `audio/`, `videos/`: ملفات القراءة والصوت والفيديو.

أُبقيت الصفحات والملفات الأساسية في جذر المشروع حالياً حتى لا تنكسر روابط GitHub Pages أو مسارات الوسائط أو بيانات الحفظ القديمة. هذا تنظيم تدريجي آمن، وليس نقلاً قسرياً للمجلدات.

## المزايا
- واجهة عربية RTL وأقسام مستقلة.
- حفظ المقاطع ومراجعتها وتتبع التقدم محلياً.
- مكتبات PDF وMP3 وMP4.
- واجهة PWA قابلة للتثبيت وتخزين ملفات التطبيق الأساسية للعمل دون اتصال بعد التحميل الناجح.
- لا يوجد حساب مستخدم أو إرسال تقدم الحفظ إلى خادم.

## تشغيل المشروع محلياً

> يجب تشغيله عبر خادم محلي؛ فتح `index.html` مباشرة عبر `file://` لا يفعّل Service Worker.

### باستخدام Python
```bash
python3 -m http.server 8000
```
ثم افتح: http://localhost:8000

### باستخدام VS Code
يمكن استعمال إضافة Live Server ثم فتح عنوان localhost الذي توفره.

## النشر على GitHub Pages
1. أنشئ مستودعاً جديداً باسم `riwaq-almutun`.
2. ارفع محتويات هذا المجلد إلى الفرع الرئيسي.
3. من Settings ثم Pages اختر النشر من الفرع الرئيسي `/ (root)`.
4. افتح رابط الموقع مرة واحدة مع اتصال بالإنترنت لتخزين ملفات التطبيق.
5. بعد ذلك يمكن فتحه دون اتصال من نفس الجهاز والمتصفح.

## إضافة متن أو مقاطع جديدة
حرّر ملف `mutun.json` الموجود في جذر المشروع. الملف عبارة عن مصفوفة من المتون، لذلك أضف كل متن كعنصر داخل المصفوفة:

```json
[
  {
  "id": "unique-matn-id",
  "title": "اسم المتن",
  "subject": "العلم",
  "description": "وصف مختصر",
  "items": [
    {
      "id": "unique-item-id",
      "reference": "الباب أو رقم البيت",
      "text": "النص المضبوط بعد مراجعته",
      "note": "شرح مختصر موثق أو ملاحظة"
    }
  ]
  }
]
```

يجب أن يكون `id` فريداً لكل متن ولكل مقطع داخله. افحص صحة البيانات بالأمر `node Validate.mjs`. بعد تحديث ملفات التطبيق أو البيانات، ارفع رقم إصدار `CACHE` في `sw.js` حتى تُحمّل الأجهزة النسخة المحدّثة.

## إضافة شروح الفيديو
ضع ملفات MP4 في مجلد `videos/`، ثم أضف بيانات الدرس إلى `videos.json` وفق المثال الموجود في `videos/README.md`. تحقق من عنوان الدرس واسم الشارح والمصدر قبل النشر. ملفات الفيديو قد تكون كبيرة، لذا أضفها بحذر عند تجهيز العمل دون اتصال.

## تنبيه علمي
هذه نسخة تقنية أولية وليست تحقيقاً علمياً للمتون. البطاقات التي تحمل وصفاً بأنها مكانية ليست نصوصاً أصلية. لا تنشر متنًا أو شرحاً قبل مقابلة النص على طبعة موثوقة، وتوثيق المصدر والطبعة والجزء/الصفحة عند الحاجة، ومراجعة أهل الاختصاص.

## فحص البيانات تلقائياً
يوجد سير عمل GitHub Actions في `.github/workflows/validate.yml` يفحص `mutun.json` عند كل `push` أو `pull request`.

## الخصوصية
التقدم محفوظ محلياً في `localStorage` على الجهاز والمتصفح الحالي. لا يوجد حساب مستخدم أو إرسال بيانات إلى خادم في هذه النسخة. مسح بيانات المتصفح قد يؤدي إلى فقدان التقدم.
